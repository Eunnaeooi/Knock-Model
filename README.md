# 노크 — 사회적 고립 예방 및 대응을 위한 AI 에이전트

제14회 2026 빅콘테스트 · AI데이터활용분야 · 팀 노크

<br>

## 1. 프로젝트 소개

**노크(KNOCK)** 는 주민등록 인구, 유동인구, 카드 소비 데이터를 활용해 강남구와 춘천시의 중장년 사회적 고립 위험을 지역별로 살펴보는 AI 에이전트입니다. 행정동별 위험 특성을 분석해 지역을 유형화하고, 지자체가 예방 활동에 활용할 수 있도록 주요 위험 요인과 대응 방안을 제시합니다.

- **대상:** 서울 강남구 22개 동 · 강원 춘천시 25개 동 (2025년 7\~12월), 50\~60대 남성 1인 가구 우선
- **산출물:** 위험 유형 5종(HH1 / HH2 / HL / LH / LL) · 위험도 5단계 · 유형별 원인 분석(SHAP)

**관련 저장소**

| 저장소 | 내용 |
|---|---|
| **Knock-Model** | 데이터 전처리 · EDA · 군집 모델링 → 결과 파일(`artifacts/`) |
| [**knock**](https://github.com/OvO-Hi/knock) | 결과 파일(`artifacts/`) → AI 에이전트 · 우선 동 지도 · 담당자용 브리프 |

## 2. 분석 방법

### 2.1 파생변수

| 축 | 파생변수 | 정의 | 위험 방향 |
|---|---|---|---|
| 인구축 | 1-1 `HH1_EXPO_5060` | 1인 세대 비율 × 5060 인구 비중 | 높을수록 |
| 인구축 | 1-2 `MALE_SHARE_5060` | 5060 인구 중 남성 비율 | 높을수록 |
| 인구축 | 1-3 `VISIBLE_IDX_50P` | (유동인구 중 5060 비중) ÷ (10세 이상 주민 중 5060 비중) | 낮을수록 |
| 지역축 | 2-1 `TIME_ENTROPY` | 하루 유동인구의 시간대(0\~23시) 분포 엔트로피 | 낮을수록 |
| 지역축 | 2-2 `POP_DENSITY` | 총인구 ÷ 면적(km²) | 낮을수록 |

- 신한카드 소비 데이터는 가맹점 시군구 단위라 군집에는 넣지 않고 EDA에서 소비 특성을 해석하는 데만 썼습니다.
- 변수 설명은 [`variable_dictionary.md`](artifacts/variable_dictionary.md), 데이터 출처는 [`출처목록.md`](public_data/출처목록.md)에 있습니다.

<br>

### 2.2 모델링 절차

| 단계 | 내용 |
|---|---|
| ① 변수 점수화 | 강남·춘천의 밀도 차이를 없애려고 **시군구 안에서** 5분위 점수(1\~5, 5 = 위험)로 변환 |
| ② 두 축 점수 | 인구축 = 1-1·1-2·1-3 평균, 지역축 = 2-1·2-2 평균 (동일 가중) |
| ③ 기본 모델 | 선행연구(김소연 외, 2024)와 같은 5분위 축 점수 + K-means. 엘보우·실루엣으로 **K=4** |
| ④ 튜닝 → 최종 모델 | 입력 공간 4 × 알고리즘 4 × K 4 = **64개 조합** 비교 → 안정성이 가장 높고 최고위험 동을 따로 분리하는 **시군구 내 z-score 축 점수 + K-means, K=5** 선택 |
| ⑤ 군집 이름 | 군집 중심의 5분위 축 점수가 3점 이상이면 H, 미만이면 L. 같은 사분면이 둘이면 더 위험한 쪽이 1번 → HH1 / HH2 / HL / LH / LL |
| ⑥ 위험도 5단계 | 두 축 점수의 합(2\~10점)을 47개 동 기준 5분위로 나눔. 같은 단계 안에서는 5060 인구가 많은 동이 우선 |
| ⑦ 검증·설명 | 부트스트랩 안정성, 민감도 분석, 대리 모델(랜덤포레스트) + SHAP으로 동별 판별 근거 |

> 군집은 **대응 유형**, 위험도는 **개입 우선순위**로 씁니다.

<br>

**기본 모델과 최종 모델 비교**

| 지표 | 기본 모델 (5분위, K=4) | 최종 모델 (z-score, K=5) |
|---|---|---|
| 실루엣 계수 (↑) | 0.474 | 0.435 |
| Davies-Bouldin 지수 (↓) | 0.658 | 0.693 |
| 부트스트랩 안정성 ARI (↑) | 0.771 | **0.807** |
| 최소 군집 크기 | 10개 동 | 6개 동 |

튜닝의 64개 조합은 같은 조건(K-means 초기값 30회, 부트스트랩 100회)으로 학습했습니다. 기본 모델의 K 선택(실루엣 0.471)은 초기값 50회 기준입니다.

## 4. 폴더 구성

```
Knock-Model/
├─ run_all.py              전체 실행 (전처리 → 튜닝 → 군집 → 검증 → 설명)
├─ preprocessing/          원본 → DB 테이블, 파생변수 (스크립트 4개)
├─ database/               ERD, 전처리 결과 테이블, features.csv (모델 입력)
├─ modeling/               common · plot_style · tune → cluster → validate → xai_explain

├─ artifacts/              에이전트 입력 데이터 · 검증 표 · figures/ · tuning/

```

| 폴더 | 내용 |

### 5.3 전체 실행 (`run_all.py`)

저장소 루트(`Knock-Model/`)에서 실행합니다. 각 스크립트를 차례로 실행하고, 한 단계가 실패하면 멈춥니다.

```bash
python run_all.py
```

| 명령 | 실행 단계 | 필요한 데이터 |
|---|---|---|
| `python run_all.py` | `cluster` → `validate` → `xai_explain` | 저장소만으로 실행 (`features.csv`, `tuning_results.csv`) |
| `python run_all.py --tune` | `tune`부터 (10분 이상) | 저장소만으로 실행 |
| `python run_all.py --prep` | 전처리 4개(`prep_features` 포함)부터 전부 | `private_data/`, `2. 경계/` |
| `--dry-run` (위 명령에 붙임) | 저장하지 않고 검증과 기존 파일 비교만 | |

- 각 스크립트는 저장 전에 같은 이름의 기존 파일과 내용을 비교해 `기존 파일과 동일 / 다름 / 새 파일`을 출력합니다.
- 그래프 한글 표시에 나눔고딕(NanumGothic) 글꼴이 필요합니다.
- 스크립트는 하나씩 따로 실행할 수도 있습니다 (예: `python modeling/cluster.py --dry-run`).

### 5.4 노트북

`notebooks/`의 두 노트북은 분석 과정과 해석을 담은 기록입니다.

- Jupyter 환경(JupyterLab, VS Code 등)에서 커널을 `requirements.txt`를 설치한 환경으로 지정한 뒤 전체 셀을 실행합니다.
