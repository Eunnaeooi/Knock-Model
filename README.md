# 노크 — 사회적 고립 예방 및 대응을 위한 AI 에이전트

제14회 2026 빅콘테스트 · AI데이터활용분야 · 팀 노크

## 1. 프로젝트 소개

50\~60대는 고독사의 63%를 차지하지만(보건복지부, 2024) 노인·청년과 달리 전담 정책이 없는 사각지대입니다. 사회적 고립은 설문으로만 측정해 와서 지자체가 동 단위로 상시 파악하기도 어렵습니다.

이 프로젝트는 설문 없이 주민등록·SKT 유동인구 데이터로 **행정동 단위 중장년 고립 위험**을 지수화하고, 그 결과를 지자체 복지 담당자용 AI 에이전트에 제공합니다.

- **대상:** 서울 강남구 22개 동 · 강원 춘천시 25개 동 (2025년 7\~12월), 50\~60대 남성 1인 가구 우선
- **산출물:** 위험 유형 5종(HH1 / HH2 / HL / LH / LL) · 위험도 5단계 · 유형별 원인 분석(SHAP)

| 저장소 | 내용 |
|---|---|
| **Knock-Model** | 데이터 전처리 · EDA · 군집 모델링 → 결과 파일(`artifacts/`) |
| [**knock**](https://github.com/OvO-Hi/knock) | AI 에이전트 — 이 저장소의 `artifacts/` 결과를 `data/`에 넣어 사용 |

## 2. 분석 방법

### 2.1 파생변수

| 축 | 파생변수 | 정의 | 위험 방향 |
|---|---|---|---|
| 인구축 | 1-1 `HH1_EXPO_5060` | 1인 세대 비율 × 5060 인구 비중 | 높을수록 |
| 인구축 | 1-2 `MALE_SHARE_5060` | 5060 인구 중 남성 비율 | 높을수록 |
| 인구축 | 1-3 `VISIBLE_IDX_50P` | (유동인구 중 5060 비중) ÷ (10세 이상 주민 중 5060 비중) | 낮을수록 |
| 지역축 | 2-1 `TIME_ENTROPY` | 하루 유동인구의 시간대(0\~23시) 분포 엔트로피 | 낮을수록 |
| 지역축 | 2-2 `POP_DENSITY` | 총인구 ÷ 면적(km²) | 낮을수록 |

- 신한카드 소비 데이터는 가맹점 시군구 단위라 군집에는 넣지 않고 EDA에서 소비 특성을 해석하는 데만 썼습니다.
- 변수 설명은 [`variable_dictionary.md`](artifacts/variable_dictionary.md), 데이터 출처는 [`출처목록.md`](public_data/출처목록.md)에 있습니다.

### 2.2 모델링 절차

| 단계 | 내용 |
|---|---|
| ① 변수 점수화 | 강남·춘천의 밀도 차이를 없애려고 **시군구 안에서** 5분위 점수(1\~5, 5 = 위험)로 변환 |
| ② 두 축 점수 | 인구축 = 1-1·1-2·1-3 평균, 지역축 = 2-1·2-2 평균 (동일 가중) |
| ③ 기본 모델 | 5분위 축 점수 + K-means, K=4 (실루엣 0.471) |
| ④ 튜닝 → 최종 모델 | 입력 공간 4 × 알고리즘 4 × K 4 = **64개 조합** 비교 → 안정성이 가장 높은 **시군구 내 z-score 축 점수 + K-means, K=5** 선택 |
| ⑤ 군집 이름 | 군집 중심의 축 점수가 3점 이상이면 H, 미만이면 L (인구축·지역축 순). 같은 사분면에 군집이 둘이면 점수 합이 큰 쪽부터 번호 → HH1 / HH2 / HL / LH / LL |
| ⑥ 위험도 5단계 | 두 축 점수의 합(2\~10점)을 47개 동 기준 5분위로 나눔. 같은 단계 안에서는 5060 인구가 많은 동이 우선 |
| ⑦ 검증·설명 | 민감도 분석, 의사결정나무, 랜덤포레스트 대리 모델 + SHAP으로 동별 판별 근거 |

> 군집은 **대응 유형**, 위험도는 **개입 우선순위**로 씁니다.

## 3. 주요 결과

### 3.1 최종 모델 선택

| 지표 | 기본 모델 (K=4) | 최종 모델 (K=5) |
|---|---|---|
| 실루엣 계수 (↑) | 0.474 | 0.435 |
| Davies-Bouldin 지수 (↓) | 0.658 | 0.693 |
| 부트스트랩 안정성 ARI (↑) | 0.771 | **0.807** |

분리도는 기본 모델이, 안정성은 최종 모델이 앞섭니다. 최종 모델은 기본 모델의 HH 15개 동을 HH1·HH2로 나눠 최고위험 동을 따로 골라낼 수 있어 최종 모델로 선택했습니다. 대리 모델(랜덤포레스트)은 최종 군집을 정확도 0.71(반복 5-fold × 20)로 재현합니다.

### 3.2 군집 유형

| 군집 | 동 수 (강남/춘천) | 특성 | 소속 동 (예) |
|---|---|---|---|
| **HH1** 극고위험 | 6 (1/5) | 다섯 변수 모두 위험. 사람과 동네가 모두 취약 | 춘천 서면·남면·동산면·북산면·남산면, 강남 삼성1동 |
| **HH2** 고위험 | 10 (7/3) | 인구밀도가 낮고 5060이 거리에서 덜 보임 | 강남 역삼1동·논현2동·대치2동, 춘천 사북면·신동면 등 |
| **HL** | 11 (6/5) | 중장년 1인 세대는 많지만 붐비는 도심 | 강남 삼성2동·대치4동·역삼2동, 춘천 후평1동·효자2동 등 |
| **LH** | 11 (4/7) | 5060이 거리에서 잘 보이나 주변 밀도는 낮음 | 강남 세곡동·일원본동, 춘천 동면·동내면·근화동 등 |
| **LL** 상대적 저위험 | 9 (4/5) | 하루 종일 사람이 오가는 고밀 주거지 | 강남 개포1동·개포2동, 춘천 퇴계동·석사동 등 |

### 3.3 최우선 개입 (위험도 5단계, 10개 동)

| 시군구 | 동 |
|---|---|
| 춘천시 (7) | 서면 · 남면 · 동산면 · 북산면 · 남산면 · 신동면 · 사북면 |
| 강남구 (3) | 삼성1동 · 역삼1동 · 논현2동 |

5단계 10개 동은 모두 HH1·HH2에 속합니다. 강남 삼성1동은 업무지구라 유동인구 영향으로 위험이 과대평가됐을 수 있어, 에이전트에서 실제 고립 여부를 먼저 확인하는 **탐색지구**로 표시합니다.

## 5. 설치 및 실행

### 5.1 실행 환경

- Python 3.9 (Windows 11에서 확인)
- 라이브러리 버전은 `requirements.txt`에 있습니다.

```bash
python -m venv .venv
.venv\Scripts\activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

### 5.2 데이터 준비

| 위치 | 내용 | 저장소 포함 |
|---|---|---|
| `public_data/` | 주민등록 인구·세대, 행정동 면적, 행정동 코드 | 포함 |
| `public_data/2. 경계/` | 2025년 2분기 시도·시군구·행정동 경계 shp | 미포함 (용량) — 아래 방법으로 직접 넣기 |
| `private_data/2026빅콘테스트_신한카드_데이터_레이아웃/` | 신한카드 결제 데이터 (`신한카드_빅콘테스트2026_데이터1.txt`, `데이터2.txt`) | 미포함 (빅콘테스트 제공) |
| `private_data/2026빅콘테스트_sk통신인구_데이터_레이아웃/` | SKT 유동인구 월별 파일 18개 (`flow_{age,wkdy,time}_pop_2025MM.csv`) | 미포함 (빅콘테스트 제공) |

**행정구역 경계 넣는 방법**

1. [공공데이터포털](https://www.data.go.kr/data/15129688/fileData.do)에서 `국가데이터처_SGIS 행정구역 통계 및 경계_20250630`을 내려받아 압축을 풉니다.
2. 압축을 푼 폴더 안의 `국가데이터처_SGIS 행정구역 통계 및 경계\2. 경계` 폴더를 통째로 `public_data/`에 복사합니다.

```
public_data/2. 경계/
├─ 1. 2025년 2분기 기준 시도 경계/
├─ 2. 2025년 2분기 기준 시군구 경계/bnd_sigungu_00_2025_2Q.shp (+ .dbf .shx .prj .cpg)
└─ 3. 2025년 2분기 기준 행정동 경계/bnd_dong_00_2025_2Q.shp (+ .dbf .shx .prj .cpg)
```

입력 파일이 없으면 스크립트가 없는 파일 목록을 출력하고 멈춥니다.

### 5.3 전처리 실행

```bash
python preprocessing/prep_admin_population.py
python preprocessing/prep_card.py
python preprocessing/prep_flow.py
python preprocessing/prep_flow_monthly.py
```

- 위 순서대로 실행합니다. `prep_flow_monthly.py`는 `prep_flow.py`의 결과를 읽으므로 반드시 그 다음에 실행합니다.
- 저장소 루트(`Knock-Model/`)에서 실행합니다. 경로는 `preprocessing/common.py`가 저장소 루트를 기준으로 잡기 때문에 다른 폴더에서 실행해도 같은 위치를 읽고 씁니다.
- `--dry-run`을 붙이면 저장하지 않고 검증과 기존 파일 비교만 합니다.
- 각 스크립트는 저장 전에 `database/`의 같은 이름 파일과 내용을 비교해 `기존 파일과 동일 / 다름 / 새 파일`을 출력합니다.

| 스크립트 | 입력 | 만드는 테이블 (`database/`) |
|---|---|---|
| `prep_admin_population.py` | `public_data/` | `SGG_MST`, `EMD_MST`, `POP_SEX_AGE`, `HH_SIZE` |
| `prep_card.py` | `private_data/…신한카드…/` | `CARD_SPEND_TIME`, `CARD_SPEND_RESID` |
| `prep_flow.py` | `private_data/…sk통신인구…/`, `2. 경계/` | `FLOW_POP_SEX_AGE`, `FLOW_POP_WKDY`, `FLOW_POP_TIME` |
| `prep_flow_monthly.py` | `FLOW_POP_*` | `flow_age_monthly`, `flow_day_monthly`, `flow_time_monthly` |

### 5.4 노트북 실행

`eda/EDA.ipynb` → `modeling/Clustering.ipynb` 순서로 실행합니다. 두 노트북은 `database/`의 테이블을 읽습니다.

- VS Code에서는 노트북 오른쪽 위 **커널 선택**에서 `.venv` 환경을 고른 뒤 **모두 실행**합니다. 경로는 노트북이 저장소 루트를 찾아 `database/`로 맞춥니다 (Colab에서는 Drive의 `빅콘/DATA/DB/`).
- 그래프 한글 표시에 나눔고딕(NanumGothic) 글꼴이 필요합니다.
- `Clustering.ipynb`는 튜닝(64개 조합 × 부트스트랩 100회) 때문에 실행에 10분 이상 걸립니다.
